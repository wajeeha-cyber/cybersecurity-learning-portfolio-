## Skills and Tools Practiced

- **Manual QA:** Writing test cases, checking positive and negative flows, documenting expected and actual behavior, and communicating test outcomes.
- **Web fundamentals:** HTTP requests/responses, redirects, cookies, authentication flows, and browser network inspection.
- **Security labs:** Broken access control, insecure direct object references (IDOR), and introductory API security concepts in authorized PortSwigger labs.
- **Linux and networking:** \`ip\`, \`ss\`, \`getent\`, \`ping\`, and \`curl\`; basic routing and listening-port interpretation.
- **Tools:** Browser Developer Tools, Burp Suite Community Edition, command-line utilities, Linux virtual machines, and Markdown reports.

**Experience level:** These are learning exercises. I do not present them as production vulnerability discoveries, professional client engagements, or proof of full security coverage.

## Responsible Testing

- Testing described here was performed on my own systems, public demo functionality, or explicitly authorized training labs.
- Lab vulnerabilities are **educational demonstrations**. They are not bug bounty findings on real production targets.
- Credentials, private data, tokens, and third-party information should not be published.
- A successful HTTP response, open port, or missing cookie attribute does not by itself establish a vulnerability.
